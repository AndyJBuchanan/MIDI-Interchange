# Plan: track export channel and header controls

Status: **built and studio-tested** (2026-11-13). Branch: `feature/track-export-channel` from updated `main`.

Give each track an optional MIDI export channel through its colour box, and tidy the header controls.

## Header layout

- Track controls: `[colour/channel]  [M][S]  Track name`.
- Colour, M and S boxes are the same size (currently M/S are 22 × 22 px).
- M and S sit directly adjacent, both in track headers and in the top panel. Keep a small gap between the track colour box and the M/S pair.
- Preserve the established mute/solo behaviour and colours.
- With no channel override, the colour box has no text. With an override, show its channel number, **1–16**, centred on the track colour.
- Choose black or white text for contrast with the selected colour. The tooltip identifies the colour/channel control and says either “Original channels” or the selected export channel.

## Colour/channel popup

- Clicking the colour box opens a compact popup anchored to that box.
- Include a colour palette and **More colours…**, which opens the full colour picker with the current track colour selected.
- Include **Export MIDI channel:** with **Original channels** and **1–16**. Mark the current choice.
- Choosing a palette colour or channel applies that choice and closes the popup. Clicking outside or pressing Esc dismisses it without changing anything further. Cancelling the full colour picker keeps the previous colour.
- Colour and channel are independent settings; changing either does not reset the other.
- Keep the full picker as a separate dialog. Qt's non-native `QColorDialog` can be embedded with `DontUseNativeDialog` and `NoButtons`, but the compact popup avoids embedding that larger UI here. Reference: [Qt QColorDialog documentation](https://doc.qt.io/qt-6/qcolordialog.html).

## Export behaviour

- Default: **Original channels**. A deliberately multi-channel track keeps its existing channels.
- An override applies to **every clip on that track**, regardless of source. On Save MIDI and drag-out, all messages with a MIDI channel use the selected channel: notes, controllers, program changes, pitch bend and pressure, including messages generated by range/trim edge handling.
- Apply it in Whole, Preserve, Rebase and Separate exports. Track/range inclusion and mute/solo determine which tracks export exactly as before.
- Preserve timing, note lengths, event order, track names, range names and filenames. Meta events and SysEx without a channel remain unchanged.
- This is an export setting. Do not rewrite source events or clip event lists. Returning to Original channels immediately restores the original channel behaviour.
- Moving or copying a clip onto another track uses the destination track's override. An override remains on its track as clips are added or removed.
- Default for newly created tracks: Original channels, including tracks created by moving/copying a clip. Do not infer an override from the incoming MIDI or the source track.
- Mapping several original channels to one intentionally combines their channel messages. Preserve the existing deterministic event order; do not add a new instrument/controller conflict-resolution policy in this feature.
- Each accepted colour or channel change is one undo step; undo/redo restores the setting and header display. Dismissing the popup or choosing the current value creates no undo step.

## Implementation

- Add an optional export-channel field to `Track`, preserved by track copies and workspace undo snapshots. Display 1–16; convert to MIDI's 0–15 representation in one place.
- Put export-channel mapping in one shared output path used by Whole and range exports, after existing clipping/state-carry rules have produced their messages. Copy output messages when applying the override.
- Keep the controller mutation and notification path responsible for undo and refreshing the header. Reuse the existing colour mutation path.
- Build one colour/channel popup for track headers. Use one shared M/S size and spacing convention for track and top-panel controls.
- Existing source-channel information continues to describe the source; the box and tooltip identify the override separately.

## Verification

- Headless UI: equal control sizes, adjacent M/S pairs, separation from colour, popup choices/current selection, contrasting channel text, clearing the override and undo/redo.
- Export/reparse: a mixed-source, mixed-channel track exports unchanged by default; an override maps all channel messages to the chosen channel through both Save and drag-out, in every mode.
- Include trimmed notes, generated note-offs and carried controller/program state at range boundaries. Check channels 1 and 16, channel 10, and resetting to Original channels.
- Verify source events are unchanged after exporting; moving/copying clips uses the destination setting; track copies and undo snapshots retain the setting.
- Regression: mute/solo, locked/unlocked ranges, track membership, export filenames and duplicate filenames retain their current behaviour.
- Studio: use the colour/channel popup, then drag/save mixed-channel clips into Cubase and Reason. Compare Original channels with an explicit override and confirm the resulting track/channel layout. Check light/dark colours, numbers 1–16, narrow track panels and both M/S pairs.
